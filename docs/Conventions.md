# Documentation and API conventions

## Names

- Entity Components end in `Component` and derive from Core `Component` when attached to `CombatEntity`.
- Immutable/reusable configuration is usually named `Profile`; reusable attack/animation data may be called a Definition.
- Operations are owned by a system `Resolver`.
- Operation outcomes use a system-specific `Result`; observed facts use an `Event`.
- Adapters form boundaries to Roblox representations, renderers, or transports.

These are conventions, not mandatory classes: some systems intentionally do not implement every role.

## Frames and IDs

Combat timing is expressed using non-negative Simulation Frames where the API requires frame values. `GameTime.Time` is derived from the fixed timestep. Entity IDs are generated by `IdGenerator`; AttackInstance has its own execution ID. NetworkSequence is transport ordering, not a simulation frame. Plugin ID/version fields identify Plugin definitions and their per-World runtime.

## Result and error policy

Expected runtime outcomes are returned as explicit results where a Resolver provides them (for example blocked, missing, conflict, invalid sequence, or unsupported state). Constructor misuse and violated programming contracts commonly use `assert`. Do not wrap all programming errors as a successful-looking Result. `APIResult` is `{ Success, Value, Error }`; `APIError.Code` currently includes `InvalidArgument`, `InvalidEntity`, `InvalidOperation`, `NotFound`, `AlreadyExists`, `NotInitialized`, `Disabled`, `PermissionDenied`, `InternalError`, and `Destroyed`. System-specific Results have their own Type/code sets; consult their source enum and tests.

## Events

Events are immutable fact envelopes or typed system records. Event Type names for the public bus are declared by `Events/EventTypes.lua`. Listener priority sorts descending; equal priorities use registration order. A callback failure is isolated by EventBus and recorded in its error list.

## Determinism and versions

Avoid wall-clock time, render callbacks, unseeded randomness, and unordered iteration as combat decision inputs. Sort at the boundary when ordering is part of the result contract. Plugin dependency version comparison supports numeric `major.minor.patch` only. The CombatAPI repository has no formal framework release version or compatibility/deprecation policy yet; module existence does not alone guarantee cross-version compatibility.

## Public vs implementation detail

Use documented constructors, methods, Results, Events, and World getters. Do not mutate internal caches, queues, Components maps, or underscored methods. The current Lua module environment does not provide a hostile-code sandbox; this is an API and ownership convention for trusted project modules.


## Dados opacos de ataques (`CustomData`)

`CustomData` é um campo de extensão opaco nas propriedades de ataque, não um espaço para callbacks ou objetos Roblox. Aceite somente tabelas simples serializáveis: sem metatables, ciclos, funções, Instances/userdata ou números não finitos; limite de 256 valores (a tabela raiz conta) e profundidade 8. A API copia e congela recursivamente o valor; tabelas vazias equivalem a `nil`. A ordem de `pairs` não é um contrato: gameplay deve ler chaves conhecidas ou ordenar chaves antes de uma iteração que afete resultados.

`CustomDataOverrides` é específico de uma `AttackInstance` e faz merge raso sobre o dado da definição. Uma tabela aninhada no override substitui por completo a tabela aninhada base. Não mutar a definição para representar estado de carga/execução; passe os dados específicos na criação da instância. Dados usados no combate, rollback ou replay devem derivar de inputs e contadores determinísticos, nunca de relógio real, callbacks de renderização ou aleatoriedade não semeada/determinística.

O contrato de snapshot está na versão **CombatStateSchema 3**, o manifest de
ataque na versão **2** e o manifest de ações na versão **2**; estas versões
internas não alteram `CombatAPI.Version`, atualmente **1**. A política SemVer e
depreciação está em [PUBLIC_API](PUBLIC_API.md). Veja [CUSTOMDATA](CUSTOMDATA.md).
